feat: board sharing (owner/editor/viewer), modal fixes, broader test coverage

Board sharing
- Database (supabase/migrations/20260101000005_board_sharing.sql):
  * board_members (editor/viewer) and board_invites; the owner stays boards.created_by.
  * Invites stay pending until the invitee accepts with a CONFIRMED email, so an
    inviter cannot learn whether an address has an account and an unconfirmed
    sign-up cannot claim invites. Max 50 pending invites per board.
  * RLS rewritten per command: members read; owner and editors write; only the
    owner renames/deletes the board and manages members; members can leave.
    SECURITY DEFINER helpers (is_board_owner / is_board_member / can_edit_board /
    my_confirmed_email) only answer about the current user.
  * Memberships and invites are written only through RPCs (invite_to_board,
    accept_board_invite). move_cards / move_columns now require edit permission
    instead of ownership.
- Client: roles on boards, ShareBoardDialog (invite, change role, remove, revoke,
  leave), received-invites panel, "shared" badge in the boards list, read-only UI
  for viewers (no drag/add/edit; RLS stays the authority), boards/roles refresh
  on realtime reconnect.
- No email is sent: "Copy invite message" gives the owner ready-to-send text
  (lib/sharing/messages.ts).

Fixes
- Modal: now uses useFocusTrap. Fixes (each reproduced by a test first):
  * focus was stolen from the field being typed in whenever the parent re-rendered
    with a new onClose (e.g. on every realtime update);
  * Escape in a nested dialog (card + delete confirm) closed both;
  * body scroll could stay locked after nested modals unmounted together
    (new ref-counted lib/scrollLock.ts).
- sanitize: redact new-style Supabase secret keys (sb_secret_...).
- Replace hard-coded text-[13px] with the text-meta token (5 files); scroll-smooth
  with data-scroll-behavior on <html>.

Tests (npm test: unit + jsdom, 98 tests; npm run test:db: 25 tests)
- Pure logic: conflict, optimistic, mutationQueue, reconcile, sanitize, scrollLock,
  roles/errors/messages.
- Components (jsdom): Modal focus, nested Escape, scroll lock, focus return.
- Database (PGlite = real Postgres, no Supabase connection): tenant isolation,
  roles, invites and RPC permissions. Mutation-checked against 8 permission
  regressions.
- vitest.config.ts: '@' alias, JSX for component tests; vitest.db.config.ts.

Deploy order: back up, run migration 000005 in Supabase, THEN deploy this client
(it queries board_members, which does not exist before the migration).

New dev dependencies: vitest, jsdom, @testing-library/react, @testing-library/dom,
@electric-sql/pglite.
